# Retry Analyzer

Desktop-приложение для пакетного анализа Wi-Fi capture-файлов (`pcap`, `pcapng`, `cap`): для каждого файла оно находит самого активного клиента и считает долю повторно переданных кадров (Retry Rate).

**[Скачать последнюю версию](https://github.com/melvilsky/Retry-Analyzer-Releases/releases/latest)**

## Что делает приложение

Вы выбираете папку (диалогом или перетаскиванием), приложение рекурсивно находит в ней все `.pcap`, `.pcapng` и `.cap` и обрабатывает их параллельно. Для каждого файла:

1. Учитываются только кадры данных (data frames). Управляющие и служебные кадры не считаются. Широковещательные и multicast-адреса игнорируются.
2. Находятся самый активный передатчик (uplink) и самый активный получатель (downlink) по числу кадров данных. Побеждает направление с большим числом кадров, при равенстве выбирается uplink. Его MAC-адрес и становится «основным клиентом» файла.
3. **Retry Rate** = кадры с флагом Retry / все кадры данных этого клиента в выбранном направлении × 100 %.
4. Для тех же кадров собирается статистика по MCS (HT, VHT, HE): сколько кадров ушло с повтором и без него на каждом MCS-индексе.

Важно понимать границы расчёта:

- Результат относится к одному «основному» клиенту в файле, а не ко всей сети.
- Файл должен быть снят с заголовком Radiotap (802.11 + Radiotap, обычно monitor-режим). Файлы с другим типом канального уровня пропускаются.
- MCS-статистика зависит от того, записал ли сниффер MCS-информацию в Radiotap. Если её нет, кадры в MCS-таблицы не попадают, а Retry Rate считается как обычно.

## Интерфейс

- **Сводка:** число файлов, средний Retry Rate и общее число пакетов.
- **RESULTS:** таблица по файлам (файл, дата захвата, направление, всего кадров, число повторов, Retry Rate). Кнопка открывает выбранный capture в Wireshark.
- **MCS STATS:** распределение кадров и Retry Rate по каждому MCS-индексу.
- **LOGS:** журнал обработки, предупреждения и пропущенные файлы.
- **EXPORT CSV:** выгрузка результатов с выбором колонок.
- **ENGINE SETTINGS:** выбор движка (встроенный Native или TShark), число параллельных воркеров, свой бинарник движка.

Результаты хранятся во временном каталоге. Приложение ничего не записывает в папку с вашими capture-файлами.

Для обычного анализа Wireshark и TShark не нужны: движок входит в приложение. Wireshark нужен только для кнопки открытия capture-файла. TShark нужен только если вы вручную выберете его движком.

## Установка

Откройте [Releases](https://github.com/melvilsky/Retry-Analyzer-Releases/releases) и выберите сборку в разделе **Assets**:

- **Windows x64, portable `.zip`**: распакуйте весь архив и запустите `retry_ui.exe` из распакованной папки. Установка не требуется. Храните остальные файлы рядом с приложением.
- **macOS Apple Silicon, `macos-arm64.dmg`**: откройте образ и перетащите `Retry Analyzer.app` в папку **Applications / «Программы»**. Затем извлеките образ и запускайте приложение из «Программ».
- **macOS Apple Silicon, `macos-arm64.zip`**: альтернативная сборка; распакуйте архив и переместите `Retry Analyzer.app` в «Программы».

Сборки macOS пока не подписаны сертификатом Developer ID и не прошли нотариализацию Apple, поэтому macOS может потребовать подтвердить первый запуск.

Архивы **Source code**, которые GitHub показывает автоматически, содержат только файлы этого публичного репозитория. Приложение нужно скачивать из прикреплённых сборок.

## Аналитика

Приложение может отправлять анонимные события использования: запуск, выбранный движок, запуск анализа, переключение вкладок, экспорт, открытие в Wireshark. Пути к папкам, имена файлов и MAC-адреса не передаются. Отправку можно отключить иконкой статистики в шапке приложения.

Этот репозиторий содержит описание и готовые релизы. Исходный код хранится отдельно в приватном репозитории.
